# 기여 범위 판별 근거

이 문서는 팀 공유 저장소와 M4 전용 산출물에 남아 있는
역할 분담 문서, 구현 상태 문서, 병합 보고서 및 버전별 README를 기준으로
개인 기여 아카이브에 포함할 범위를 구분하기 위해 작성했습니다.

> GitHub Download ZIP에는 `.git` 커밋 이력이 포함되지 않으므로
> 개별 코드 라인의 작성자를 증명하는 문서는 아닙니다.
> 대신 팀 역할 분담과 M4 전용 산출물의 문서·코드 구조를 기준으로
> 담당 범위를 구분했습니다.

## 1. 팀 README의 역할 분담

팀 README는 M4를 다음과 같이 정의합니다.

- PAGE 1 지도
- 지역 상세
- 친구 순위
- 경쟁 메시지
- 추천 화면 이동 버튼
- PAGE 1 화면·컴포넌트·샘플 데이터·인수 안내 전달

또한 최종 Frontend 통합 책임은 M1,
PAGE 1 개발은 M4로 구분되어 있습니다.

따라서 `PAGE1_M4` 전용 패키지의 Frontend 코드와
PAGE1 수정본을 M4 기여 범위로 분류했습니다.

단, 팀 README는 역할 분담 및 개발 계획 문서이므로
이 문서만으로 개별 기능의 구현 완료를 판단하지 않고,
아래의 구현 상태 문서와 실제 산출물을 함께 확인했습니다.

## 2. PAGE1/M4 상태 문서에서 확인되는 구현

M4 전용 패키지에 포함된
`docs/PAGE1_M4_STATUS.md`에는 다음 구현 상태가 기록되어 있습니다.

- PAGE1 지도 / 랭킹 / 팝업 / 파스텔 UI
- 지역 클릭 시 시군구 랭킹 팝업
- 활동지표 / 공공데이터지표 탭
- 상승 지역 티커
- 친구 운동 랭킹 로그인 게이트
- 로그인 사용자 기준 친구 목록 조회
- 친구 코드 등록 UI 및 Mock 동작
- 지역 운동열기 일별 snapshot 구조
- PAGE2 CTA
- 울릉도 / 독도 표시
- 로그인 주소지 기반 MY REGION 마스코트
- 지역 선택 팝업 마스코트
- 로딩 / 오류 UI

추가 변경 기록에는 다음 내용도 확인됩니다.

- 17개 시·도용 2D SVG 마스코트
- `우리 동네는 지금` 영역의 지역 순위 + 마스코트
- 로그아웃 상태에서 개인 지역 정보 비노출
- 지역 팝업 지역명 옆 마스코트 표시

다만 상태 문서에는 Mock / Live 경계도 명확히 기록되어 있습니다.

Mock 모드의 로그인 및 친구 등록은
UI / Interaction 검증을 위한 브라우저 저장소 기반 구현이며,

실제 회원 인증,
친구 관계 DB 저장,
활동 기록 기반 지역 랭킹 집계 등은
Backend 통합이 필요한 영역으로 구분되어 있습니다.

따라서 본 아카이브에서는
Frontend UI 및 Interaction 구현을 M4 범위로 기록하고,
실제 Backend 영속 처리까지 개인 기여로 주장하지 않습니다.

## 3. V3 병합 보고서에서 분리 가능한 범위

V3 패키지의 `docs/MERGE_REPORT.md`는
PAGE1에서 유지한 Frontend와
WOW에서 가져온 Backend 기능을 명확히 분리합니다.

### PAGE1에서 유지

- 최종 파스텔 UI와 지도 디자인
- 울릉도 / 독도 포함 지도
- 지역 선택 팝업 UI
- 지역별 마스코트 이미지
- `우리 동네는 지금` 마스코트 / 순위 UI
- 전국 1위 마스코트 직접 모션
- `TOP 1` 표시
- 기존 반응형 CSS

### WOW에서 가져온 기능 코드

- Django API 라우팅
- 개발용 signed-cookie 로그인 세션
- 사용자 프로필 API
- 친구 등록
- 로그인 사용자별 친구 랭킹
- 일별 `RegionActivitySnapshot` 기반 지역 랭킹 계산
- 활동 완료 기록 API
- Repository / Service Layer 구조
- 데이터가 없는 기능의 `PENDING_DATA` 처리

또한 병합 과정에서는
Backend 친구 랭킹 응답 형식과
기존 Frontend LIVE Adapter의 형식 차이를 맞추는
호환성 수정이 기록되어 있습니다.

따라서 V3의 `backend/`는
개인 M4 기여 아카이브에서 제외하고,

PAGE1에서 유지된 `frontend/` 영역을
M4 Frontend 기여 범위로 분리했습니다.

## 4. 2026-09-14 PAGE1 / PAGE2 연결본

해당 버전의 `README.txt`에는 다음과 같이 기록되어 있습니다.

- PAGE1은 최종 저장본의 디자인과 기존 동작 유지
- CTA 경로만 수정
- 운동 찾으러 가기 → `recommend.html`
- 추천 화면 로고 → `index.html`
- PAGE2는 제공된 M1 HTML / CSS 사용
- Django static 경로를 상대 경로로 변경

따라서 PAGE2 자체를 M4 구현으로 분류하지 않고,
PAGE1에서 PAGE2로 이어지는 CTA 연결과
수정된 PAGE1 `index.html`만
개인 기여 아카이브에 포함했습니다.

또한 원본에는 `recommend.js`가 제공되지 않아
현재 위치 및 실제 추천 실행 기능은 준비 중 상태이며,
실제 추천 / API 연결은 포함되지 않았다고 명시되어 있습니다.

따라서 이 버전은
**PAGE1 → PAGE2 화면 이동 연결 작업**으로 기록하고,
실제 추천 기능 구현으로 표현하지 않습니다.

## 5. 지역 팝업 CTA 버전

해당 버전의 `README.txt`에는
다음과 같은 변경 내용이 기록되어 있습니다.

- 지도에서 지역 선택
- 지역 팝업 하단에 `운동 찾으러 가기` 버튼 배치
- 버튼 클릭 시 추천 페이지 이동
- 추천 페이지 상단 로고를 통해 PAGE1 복귀

특히 README에는

기존 랜딩 하단의 이동 버튼을
모든 지역에서 사용하는 팝업 안으로 옮긴 버전이라고
명확히 설명되어 있습니다.

이 변경은 PAGE1의 지역 선택 Popup과
운동추천 CTA Interaction에 해당하므로
M4 / PAGE1 기여 범위에 포함했습니다.

다만 이 버전 역시 원본에 `recommend.js`가 없어
실제 운동 추천 및 현재 위치 기능은 준비 중 상태로 기록되어 있습니다.

따라서 개인 기여 내용은
**팝업 UI와 추천 페이지 이동 CTA 구성**으로 한정하며,
실제 추천 로직까지 구현한 것으로 표현하지 않습니다.

## 6. 개인 기여 아카이브에서 제외한 영역

원본 문서와 병합 기록을 기준으로
다음 영역은 개인 M4 기여로 분류하지 않았습니다.

- Django Backend 전체
- Repository / Service Layer
- 실제 로그인 인증 시스템
- 친구 관계 DB 영속 저장
- `RegionActivitySnapshot` Backend 계산
- 활동 완료 API
- Recommendation Backend
- 공공데이터 수집 Pipeline
- M1이 제공한 PAGE2 HTML / CSS 원본
- 팀 통합 이후 다른 담당자가 구현한 전체 서비스 코드

## 7. 정리

현재 개인 아카이브에서 M4 기여로 기록하는 핵심 영역은 다음과 같습니다.

- 대한민국 지도 중심 PAGE1 Frontend
- 지역 선택 및 시군구 랭킹 Popup
- 지역 / 친구 랭킹 UI
- 상승 지역 및 순위 변화 시각화
- MY REGION UI
- 지역 마스코트
- TOP 1 Character UI / Motion
- 친구 랭킹 로그인 Gate
- 친구 코드 등록 UI / Mock
- Mock / Live Adapter 구조
- 반응형 및 파스텔 UI
- 울릉도 / 독도 표시
- PAGE2 이동 CTA
- 지역 Popup 내부 운동추천 CTA

이후 팀 통합 과정에서
전체 Frontend 구조와 디자인은 변경되었으며,

본 저장소는 현재 최종 서비스를 개인 프로젝트로 복제하는 것이 아니라
**제가 담당하거나 직접 수정한 M4 / PAGE1 Frontend 작업과
후반 Visual Asset 참여 기록을 보존하기 위한 기여 아카이브**입니다.
